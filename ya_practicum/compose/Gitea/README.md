# 🦊 Self-hosted Git-сервер Gitea с PostgreSQL

## 📋 Описание

Проект демонстрирует развёртывание self-hosted Git-сервера **Gitea** с использованием **PostgreSQL** в качестве СУБД через Docker Compose. Решение показывает, как организовать многоконтейнерное приложение с персистентным хранением данных, управлением через переменные окружения и внутренней сетью Docker.

### 🎯 Цели проекта
- Развёртывание полноценного Git-хостинга в контейнерах
- Организация связки Gitea + PostgreSQL через Docker Compose
- Использование `.env` для управления конфигурацией
- Обеспечение персистентности данных через именованные тома
- Изоляция базы данных от внешней сети (безопасность)

## 🛠  Cтек

- **Docker** & **Docker Compose** — контейнеризация и оркестрация
- **Gitea v1.24.2** — легковесный self-hosted Git-сервис
- **PostgreSQL 17 (Alpine)** — реляционная СУБД

## 📁 Структура проекта

```
Gitea/
├── compose.yml    # Оркестрация контейнеров Gitea и PostgreSQL
└── .env           # Переменные окружения (учётные данные БД)
```

## 🚀 Быстрый старт

### Предварительные требования
- Docker Engine 20.10+
- Docker Compose v2.0+
- Свободный порт `3000` на хосте

### Установка и запуск

```bash
# Клонируйте репозиторий
git clone <your-url>
cd Gitea

# Запустите контейнеры
docker compose up -d

# Проверьте статус
docker compose ps
```

### Доступ к сервисам

| Сервис | URL | Описание |
|--------|-----|----------|
| **Gitea** | http://localhost:3000 | Веб-интерфейс Git-сервера |

После первого запуска нажмите кнопку **«Установить Gitea»** на странице начальной конфигурации — установка пройдёт автоматически с подключением к PostgreSQL.

## ⚙️ Конфигурация

### Docker Compose (`compose.yml`)

**Сервис Gitea:**
- Образ: `gitea/gitea:1.24.2`
- Именованный том `git_data` для данных репозиториев
- Подключение к БД через переменные из `.env`
- `depends_on: db` — ожидание готовности PostgreSQL

**Сервис PostgreSQL:**
- Образ: `postgres:17-alpine3.22`
- Именованный том `postgres_data` → `/var/lib/postgresql/data`
- **Без проброса портов наружу** — доступна только внутри Docker-сети


## 🐛 Решённые проблемы

### Проблема 1: Gitea не подключается к базе данных
**Симптом:** При нажатии «Установить Gitea» появляется ошибка «Некорректные настройки базы данных».

**Причина:** В исходной конфигурации отсутствовал сервис PostgreSQL — Gitea пытался подключиться к несуществующей БД.

**Решение:** Добавлен сервис `db` с образом `postgres:17-alpine3.22`, с переменными окружения, согласованными с `.env` Gitea.

---

### Проблема 2: Ошибка монтирования тома PostgreSQL
**Симптом:**
```
Error: invalid mount config for type "volume": invalid mount path: 
'var/lib/postgresql/data' mount path must be absolute
```

**Причина:** В секции `volumes` был указан только путь на хосте (`./var/lib/postgresql/data`) без указания пути внутри контейнера и без имени тома.

**Решение:** Использован именованный том с полным синтаксисом:
```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data
```

---

### Проблема 3: Несоответствие имён сервисов
**Симптом:** Gitea не может разрешить хост БД.

**Причина:** В `.env` указан `DB_HOST="db:5432"`, но сервис назывался `psql`. Docker Compose использует имя сервиса как DNS-имя в внутренней сети.

**Решение:** Переименован сервис `psql` → `db` для соответствия конфигурации.

---

### Проблема 4: Конфликт порта 5432
**Симптом:**
```
Error: failed to bind host port 0.0.0.0:5432/tcp: address already in use
```

**Причина:** На хосте уже работает локальный PostgreSQL, занимающий порт 5432.

**Решение:** Убран проброс порта наружу. PostgreSQL доступен только внутри Docker-сети по адресу `db:5432` — это безопаснее и устраняет конфликт.

**Вывод:** Базы данных в контейнерах не обязательно пробрасывать наружу — если сервисы общаются внутри Docker-сети, достаточно внутренней маршрутизации через имена сервисов.
